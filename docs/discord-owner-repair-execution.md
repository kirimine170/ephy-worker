# Discord owner repairの実行境界

Discordの修正依頼は，実際のauthor ID `425581535748423680`から受けた自然文を既存ローカルLLMが分類する．表示名，引用文，モデル出力から権限を付与しない．通常会話と他の許可ユーザーは従来の調査経路を利用する．

修正proposalは，固定contract，別sessionのplanner／implementer，独立verifier，freshなread-only auditorを既存managed Piのgovernance acknowledgementとともに利用する．proposalの採用，GitHubへの送信，最終headのCIとCodex Review，merge，本番反映，再起動は別のrelease roleが扱う．受付やtest合格だけで本番反映済みとは報告しない．

## 既存モデルの観測

`external_existing_llama`は，明示的なloopback HTTP origin，listener／engine PIDと開始時刻，実行binary hash，設定hash，`/health`，`/v1/models`，`/props`が返すmodel／contextを固定する．稼働中weight bytesの暗号学的証明ではない．全roleを観測済みmodelに固定し，モデルの起動，停止，unload，設定変更を実装しない．Piのretryとcompactionは専用設定で無効にする．

## 実行コードの検証

従来のcontractはMarkdown候補だけを許可する．実行コードには明示的な`execution_profile = native_windows_code_v1`と固定した`verifier_sandbox` descriptorが必要になる．runner，governance，sandbox，release controllerなどの実行制御自体を候補scopeへ含めることはできない．

descriptorにはCodex native sandbox CLIの実行file hash，Python hash，必要なruntime read path，private root deny path，実測capability artifactとそのhashを含める．これはCodexモデル呼出しではなく，native sandboxによる固定argvの実行である．candidateとcheckerはread-onlyにし，job固有の一時領域だけを書込可能にする．command，profile，実行binary，stdout／stderr，capabilityのhashをverifier identityと各検証記録に結び付ける．

native profileの各検証commandの時間予算は，固定contractの`stage_seconds`と`timeout_seconds`の小さい方を使い，実行とinvocation identityに同じ値を結び付ける．例えば1800秒のstageと14400秒のjobなら各検証commandは1800秒となるが，実行時にはjobの残時間も上限となる．従来のMarkdown profileの各検証commandは600秒のままとする．

capabilityは，protected fileのread／write，candidate／checkerのwrite，child processの同じ操作，外部およびloopback networkへのparent／child接続，asyncio動作を実測する．タイムアウトや接続拒否だけをnetwork隔離の成功と扱わない．baselineとattemptごとに同じ対象で再検査する．成功を示すbooleanだけでは有効なdescriptorにならない．

network policyはoperatorが明示的に選ぶ．`windows_all_network_denied`はloopbackも含めた拒否を要求し，現在のWindows環境では不合格となる．`windows_external_network_denied`はparent／childとも非loopbackの強制拒否を要求するが，loopbackの到達性を別途記録し，loopbackの隔離を保証しない．選択がない場合や未知のpolicyは拒否する．モデルからpolicyを選択できない．private fileの隔離と書込制限はどちらのpolicyでも必須であり，通常のMarkdown profileは変わらない．

readonly候補がprivate親directoryのdeny ACLを継承している場合は，native sandbox専用groupに対して，固定したcandidate／checker／runtimeの狭いrootだけへ一時的なReadAndExecuteを付与する．job固有のtempには子directoryへ継承するModifyだけを付与する．pytestとGitのancestor確認のため，candidate／checker／tempとcontrol probeからprivate境界までの解決済みancestor chainにReadAttributes／Traverseだけを付与し，一覧取得や兄弟fileの内容へのアクセスは拒否する．runtime read rootのancestorにはmetadata許可を追加しない．parent／child両方で，候補とcheckerの読み取り，temp内の子directory作成，親のmetadata取得，親一覧と兄弟fileのread／write拒否を実測する．

変更前のDACLと継承状態をcandidate外へ保存してから準備し，実行後はDACLだけを復元するWindows APIで復元を検査する．ancestorのmetadata変更は継承flagと継承対象ACE bytesを保存し，MAXIMUM_ALLOWEDで開いたhandleへの[SetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo)で子へ伝播させない．owner／group／SACLは変更しない．homeやworkspace全体の内容へのdeny ACLを削除しない．全必須controlが成立しない環境では隔離能力不足として停止し，本番反映の成功へ読み替えない．
