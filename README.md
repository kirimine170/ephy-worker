# Ephy Repository Template

## Overview

This repository is the language-independent base template for repositories in the Ephy ecosystem．It provides shared metadata，documentation，issue forms，repository initialization，and validation without choosing an application stack．

## Role in the Ephy ecosystem

The template standardizes the declarations collected later by the `ephy` meta repository．Each repository declares only its parent project and its direct relationships in `.ephy/project.yaml`．It does not maintain a duplicated list of downstream repositories，and Git submodules are not used to represent ecosystem relationships．

## Goals

- Keep repository metadata machine-readable and consistent．
- Establish common documentation，security，and collaboration boundaries．
- Initialize a new Ephy repository without network or GitHub operations．
- Validate both this template and repositories initialized from it using only Python's standard library．

## Non-goals

- Selecting a programming language，framework，or build system．
- Creating GitHub repositories，changing remotes，pushing，releasing，or deploying．
- Defining organization-wide contribution，security，or conduct policies that belong in the future organization `.github` repository．
- Predicting dates，percent complete，or duration-based roadmaps without evidence．

## Current status

`ephy-repository-template` is `active`．The status describes the current implementation state，not a deadline．

## Architecture

The repository consists of declarative metadata under `.ephy/`，shared documentation under `docs/`，GitHub collaboration templates under `.github/`，and standard-library Python tooling under `scripts/`．See [Architecture](docs/architecture.md) for the responsibility boundaries．

## Repository relationships

- Parent project: `ephy`
- Direct dependencies: none
- Integrations: none
- Runtime platforms: none

Relationship rules and field meanings are documented in [Repository relationships](docs/repository-relations.md)．

## Getting started

Create a repository from this template，then run the initializer from its root:

```bash
python3 scripts/init_repository.py \
  --id ephy-cam \
  --type extension \
  --description "Camera and visual-ingestion infrastructure for Ephy" \
  --visibility private \
  --classification restricted
```

Optional repeatable flags are `--depends-on`，`--integrates-with`，and `--runs-on`．Use `--parent` and `--status` when their defaults of `ephy` and `active` are not appropriate．A first initialization replaces the template identity．Reinitializing an already initialized repository is rejected unless `--force` is explicitly supplied．

The initializer performs no network requests，GitHub API calls，or Git remote changes．After initialization，review `.ephy/project.yaml` and `README.md` before adding implementation-specific files．

## Testing

Run the complete local checks with:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_repository.py --check-sensitive-patterns
```

The validator deliberately supports the constrained YAML shape generated by this template．It is not a general-purpose YAML parser．

## Security and data handling

Secrets，unnecessary personal data，raw conversations，production Karte data，master camera images，raw LoRA training data，and model weights do not belong in normal Git history，including private repositories．See [Security and data handling](docs/security-and-data.md)．
